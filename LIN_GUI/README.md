# LIN 报文监控上位机

一个用 PyQt5 写的 LIN 总线上位机,既能**被动监听**总线上已有的报文,
也能自己充当**主节点**去轮询从节点,还能在**仿真模式**下不带任何硬件先跑起来看效果。

和仓库里的 [FLASH_Tool](../FLASH_Tool) (PCAN CAN 上位机) 是同一套代码风格,
目录结构、命名习惯、日志格式都保持一致。

---

## 1. 功能一览

| 功能 | 说明 |
| --- | --- |
| 被动监听 | 只收不发,解码总线上现有的报文(适合车上已有主节点的情况) |
| 主节点轮询 | 本机当主节点,按调度表或手工列表轮询从节点 |
| 仿真演示 | 内置仿真从节点,不用任何硬件就能验证整条软件链路 |
| LDF 解析 | 支持 LIN 1.3/2.x 的**分节语法**与 LIN 2.2 的**结构化语法**,自动填充帧名/长度/调度表 |
| 信号解码 | 按 LDF 把原始字节解码成物理值(系数/偏移/单位/逻辑值枚举) |
| 校验和检查 | 经典校验和与增强校验和都支持,校验失败的帧在列表里标红 |
| 报文统计 | 按帧 ID 统计次数、平均周期、错误数 |
| CSV 日志 | 收发报文实时落盘,可用 Excel / grep / 脚本二次分析 |
| 报文导出 | 界面上过滤后的内容可另存为 CSV |
| 自动跟随滚动 | 默认跟随最新报文；向上查看历史时暂停，回到底部后自动恢复 |
| 暂停 log | 暂停列表显示但不停止采集或 CSV；恢复时补显示缓存帧 |

## 4. 硬件连接

LIN 是单线总线,常见接法有两种。

### 4.1 USB 转串口 + LIN 收发器(最常见)

```
   STM32/PC                       LIN 总线
  ┌────────┐                  ┌──────────────┐
  │ USB-TTL│── TX ──┐         │              │
  │        │── RX ──┼──┐   ┌──┴──┐      ┌────┴────┐
  │  3V3   │── GND──┼───┼──┤TJA1│  LIN │  其它节点│
  └────────┘        │   │  │021 │      └─────────┘
                    │   └──┼──┤     │
              3.3V ─┼──────┼──┤ VCC│
                    │      │  └────┘
                   10kΩ    │
                    │      │
                   GND ────┴
```

* 收发器常用 **TJA1020 / TJA1021 / MLLIN2 / SN65HVD308**;
* 断线检测电阻 10 kΩ 上拉到 3.3 V(有些板子已经自带);
* 串口参数 **19200 / 8N1 / 无流控**。

上位机侧把串口选成这个 USB-TTL 即可。注意 **TX 与 RX 要交叉接**。

### 4.2 专用 USB-LIN 适配器

如果用的是带 MCU 的 USB-LIN 转接线(很多"USB 转 LIN"模块都是这种),
接线同上,串口参数保持 19200 8N1。模块内部一般已经把 BREAK/SYNC 做好了,
如果发现从节点不应答,可以在界面上切换"BREAK 生成方式"试试。

### 4.3 BREAK 域怎么发

LIN 的帧头第一个是 BREAK —— 至少 11 个位时间的低电平。普通 UART 发不出
"11 位以上的低电平",本程序提供两种办法(界面上可切换):

* **UART BREAK 控制位**:直接拉低 UART 的 BREAK 引脚(FTDI / CP210x / CH340 都支持);
* **波特率切换**:以 2/3 波特率发一个 `0x00`,低电平刚好持续
  `9 × 1.5 = 13.5` 个正常位时间,正好落在规范允许的 11~26 位时间内
  (与 Linux 内核 LIN 驱动 `sllin` 的做法一致)。

### 4.4 和本仓库 STM32F103 工程配合

STM32F103 **没有 LIN 外设**,所以板子上的 LIN 节点一般是这样做的:

```
STM32F103 UART ──► TJA1021/TJA1020 ──► LIN 总线
```

由此有两种常见搭配:

1. **PC 工具当主节点,STM32 当从节点**
   STM32 用 UART 收帧头(0x00 断帧 + 0x55 同步 + 受保护 ID)、
   按约定回数据 + 校验和;PC 工具选"主节点(轮询)"模式,填好帧 ID、
   数据长度、校验和类型就能轮询到它。
2. **STM32 当主节点,PC 工具旁听**
   STM32 自己在总线上跑调度表,PC 工具用另一个 USB-TTL + 收发器并联到同一条
   总线,选"被动监听"模式即可看到所有帧。

> 无论哪种方式,**双方的帧 ID、数据长度、校验和类型必须一致**,
> 最省事的做法是双方共用同一份 LDF(PC 工具可以直接加载它)。

## 5. 三种工作模式

| 模式 | 说明 | 需要硬件 |
| --- | --- | --- |
| **主节点(轮询)** | 本机发帧头,收从节点应答;按"轮询帧列表"顺序轮询 | 需要,且总线上不能有另一个主节点 |
| **被动监听** | 只收不发,还原总线上已有的报文 | 需要,总线上要有主节点在跑 |
| **仿真演示** | 内置仿真从节点,数据是递增计数器 | 不需要 |

> 被动监听依赖 LDF 里的帧长度才能准确切分帧;没有 LDF 时会退化成
> "按字节间隔"判断帧结束,可能偶尔切错。

### 轮询帧列表

右侧 **LDF / 轮询** 页:

1. 加载 LDF 后,选一张调度表点"填入轮询列表";或手工"添加"行;
2. 每行可以设置:是否轮询、帧 ID、帧名、数据长度、周期(ms)、校验和类型;
3. **周期**就是该帧在调度表里的槽位时间,程序按这个节拍轮询,
   应答超时也会被限制在槽位时间内,不会打乱调度表。

## 6. LDF 支持

支持两种语法,程序会自动识别。

**分节语法**(LIN 1.3 / 2.0 / 2.1 / ISO 17987 常见写法)

```
[LIN_Description]
LIN_Protocol_Version=2.1
Master_Node=Master
S Baudrate=19200

[Frame]
MotorControl: 0x11, Master, 2;

[Frame_Definition]
MotorControl: 2, Master, Motor_1, 2 {
  MotorSpeed, 0;
  ErrorFlag, 8;
}

[Schedule_Table]
MainTable: MotorControl delay 10 ms; MotorStatus delay 10 ms;
```

**结构化语法**(LIN 2.2)

```
Nodes { Master: CEM, 5 ms, 0.1 ms; Slaves: LSM, RSM; }
Frames { CEM_Frm1: 0x01, CEM, 1 { InternalLightsRequest, 0; } }
Schedule_tables { Normal_Schedule { CEM_Frm1 delay 15 ms; } }
```

解析器对未知关键字是"跳过而不是报错",所以各家工具导出的 LDF 基本都能打开。

## 7. 协议实现要点

### 7.1 受保护 ID(Protected ID)

帧头里的 ID 字节 = **2 个奇偶校验位 + 6 位帧 ID**:

```
P0 = ID0 ⊕ ID1 ⊕ ID2 ⊕ ID4
P1 = ¬(ID1 ⊕ ID3 ⊕ ID4 ⊕ ID5)
受保护 ID = (P1 << 7) | (P0 << 6) | (ID & 0x3F)
```

这套定义与上游 Linux LIN 驱动(`lin-bus/linux-lin`,`sllin.c`)里的官方奇偶校验表
**逐项一致**,测试 `tests/test_protocol.py` 会拿 64 个帧 ID 全表比对。

### 7.2 校验和

| 类型 | 计算内容 | 适用 |
| --- | --- | --- |
| 经典 | 只累加数据字节 | LIN 1.3、诊断帧(0x3C/0x3D) |
| 增强 | 额外累加受保护 ID 字节 | LIN 2.0+ 的普通帧 |

累加时进位回卷(每加一个字节后 >255 就减 255),最后按位取反。

### 7.3 主节点回显

LIN 主节点发送帧头时,**自己也会在总线上收到这份帧头**(收发器的 RX 直接接在总线上)。
因此上位机在收应答时要先把回显去掉。程序的处理办法是:
把"无回显 / 1 字节回显 / 2 字节回显 / 3 字节回显"几种解释都试一遍,
**用校验和来判定哪一种才是对的**,所以既不用手工配置也不会解错。

## 8. 日志格式

CSV 默认写在 `logs/linlog_YYYYmmdd_HHMMSS.csv`:

```
time,time_s,dir,id_hex,name,dlc,data_hex,checksum,checksum_type,checksum_ok,note
2026-10-22 19:05:12.345,1792664312.345000,RX,0x11,Motor_1,2,64 01,EB,enhanced,1,
```

* `dir`:`RX` 收到的 / `TX` 本机发出的;
* `checksum_ok`:`1` 校验通过,`0` 校验失败;
* `note`:超时、校验错误等备注。

界面上"导出 CSV"导出的列略有不同(是按当前过滤条件导出的视图)。

## 9. 常见问题

**Q:端口能打开,但一帧都收不到。**
A: 按顺序排查:
1. 波特率对不对(默认 19200,有些模块是 10400);
2. TX/RX 是否交叉接了;
3. BREAK 方式换成另一种(控制位 ↔ 波特率切换);
4. 是不是该用"被动监听"模式(总线上已经有主节点时,用主节点模式会冲突);
5. 串口适配器是否被别的程序占用。

**Q:帧能收到,但校验和总是不对。**
A: 校验和类型选错了。LIN 2.x 的普通帧用增强校验和,诊断帧用经典校验和。
如果总线是 LIN 1.3,把所有帧都改成"经典"试试。

**Q:被动监听切出来的帧不对。**
A: 没加载 LDF 时只能靠字节间隔猜帧边界。建议先加载对应总线的 LDF。

**Q:想接 Vector VN1610 / IXXAT 这类商用适配器。**
A: `lin_tool/transport.py` 里定义了 `LinTransport` 抽象接口,
实现 `open/close/send_header/read_bytes` 四个方法即可接入,界面不用改。
